# Patterns from the GTM video library

The local archive is useful for inspecting a real production decision, not for blindly cloning an entire previous film.

## Launch films

`channels-sdk` combines a product introduction, architecture, native-looking channel conversations, a small code change, and an installation CTA. The transferable pattern is variety of proof: each scene explains a different part of the same claim. Keep the feature/channel list in one registry and derive all scenes from it.

`aimock` starts with an engineering problem and makes code the main visual subject. Its source notes tie numerical claims to dated evidence. Generalize the structure, not the old numbers. Keep code large enough to read; a tiny editor screenshot in a decorative frame is not useful proof.

`openmuse-demo` uses layered product surfaces and diagrams with documented illustrative sequences. The key distinction is what was actually recorded versus what was animated to explain a capability. Carry that distinction into each delivery's notes.

`opendots` combines real UI clips with branded scenes and a human-editor package. The editorial lessons include theme continuity, callout safe areas, consistent channel logo sizing, a legible GitHub CTA, and source-media honesty. Preserve its workflow lessons without carrying over the old film's particular backdrop, mascots, or defects.

## UI animations and loops

A native-looking app animation needs the surface's spacing, hierarchy, and behavior, not only a matching color. Stage short readable conversations. Mount new content when it arrives. A hidden card that still participates in layout can push a message offscreen before it is ever shown.

An approval is a useful causal beat: draft → review → click → saved artifact. Don't merely change a status pill while the rest of the UI stays unchanged. The starter demonstrates a new page appearing in the sidebar and a saved receipt.

The subagent diagram demonstrates a separate format: a diagram loop should often be complete in frame zero, with movement limited to traffic that explains the topology. Shared geometry matters more than decorative motion. Route highlights on the same path as the wire, use level branches and consistent buses, and check the loop boundary.

## Improving readability

There are three distinct operations:

1. **UI zoom / density:** changes text, controls, and layout before capture. Use when the product is too small.
2. **Editorial camera:** crops or pans an existing frame to direct attention. Use deliberately; it may remove navigation or receipts.
3. **Output resolution:** changes the pixel count. Rerendering vectors at 4K adds detail to those vectors. Upscaling an existing recording does not recover detail.

Record all three independently. Don't use a larger pixel count or crop percentage as evidence that UI readability was fixed.
